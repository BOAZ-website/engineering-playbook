# 디자인 시스템 버전 관리

아래 사실은 2026-11-24 기준 design-system 저장소의 `README.md`, `CONTRIBUTING.md`, `package.json`에서, 2026-11-25 기준 `AGENTS.md`의 breaking 변경 절에서 확인함. 확인하지 못한 항목은 `[확인 필요]`로 표시

## 요약

| 항목 | 내용 |
|---|---|
| 배포 방식 | 패키지 저장소에 게시하지 않고 git 태그로 배포 |
| 설치 방식 | 앱이 저장소의 태그를 지정해 설치. 명령은 design-system 저장소 `README.md` "Installation" |
| 버전 표기 | `v주.부.수` 형식의 태그. `package.json`의 `version`과 같은 값 |
| 릴리스 | `dev` → `main` 릴리스 PR 머지 후 태그 생성 |
| 앱 반영 | 두 앱이 태그 버전을 올리는 PR을 각각 생성 |

- 근거: 두 앱이 같은 토큰과 컴포넌트를 쓰므로 반영 시점이 어긋나면 화면이 달라짐

## 버전 이력

| 버전 | 내용 |
|---|---|
| `v0.1.0` | 파운데이션 토큰. 2026-10-11 |
| `v0.1.1` | radius 토큰 1종 추가 |
| `v0.2.0`(예정) | React 컴포넌트 첫 포함. 불러오는 경로에 앱 이름(`home`) 추가 |

## 버전 규칙

| 변경 종류 | 예 | 버전 변화 |
|---|---|---|
| 호환되는 추가 | 토큰 추가 | 수 자리 증가(선례: `v0.1.0` → `v0.1.1`) |
| 불러오는 경로·이름이 바뀌는 변경 | 경로에 앱 이름 추가 | 부 자리 증가(선례: `v0.1.x` → `v0.2.0`) |
| 그 밖의 호환되지 않는 변경 | 토큰·컴포넌트 삭제, 이름 변경 | 토큰 이름 삭제·변경은 부 자리(0.x) 또는 주 자리 증가. PR 본문에 대체 이름과 영향 앱을 적음(2026-11-25 기준 `AGENTS.md` "breaking 변경"). 값만 바뀌거나 토큰만 추가되면 수 자리 증가 |

- 버전이 `1.0.0` 미만인 동안에는 부 자리 증가에 호환되지 않는 변경이 들어갈 수 있음. 앱은 버전을 올릴 때마다 변경 내용을 확인
- 버전별 변경 내용: design-system 저장소의 Releases 목록

## 릴리스 절차

| 순서 | 작업 | 담당 |
|---|---|---|
| 1 | `dev`에 릴리스할 변경이 모였는지 확인 | PM |
| 2 | `package.json`의 `version`을 올리는 PR을 `dev`에 머지 | Product Engineer |
| 3 | `dev` → `main` 릴리스 PR 생성 | Product Engineer |
| 4 | 리뷰어 승인과 검사 통과 후 merge commit으로 머지 | Product Engineer(PR 작성자) |
| 5 | 릴리스 태그 생성 | PM(디자인 시스템 저장소 문서에는 디자인 시스템 리드로 적혀 있음) |

- 순서 2와 3은 `v0.1.1` 릴리스의 선례(버전 지정 PR, 릴리스 PR)를 따름
- 빌드 결과(`dist/`)는 커밋에 포함되어 있어 태그만으로 설치 가능
- 릴리스 PR 제목: 통일 기준은 `[Release] 내용`. 선례는 `[Chore] v0.1.1 릴리스`

## 두 앱의 반영 방법

| 순서 | 작업 | 담당 |
|---|---|---|
| 1 | 릴리스 태그 생성 확인 | Product Engineer |
| 2 | 웹사이트에서 설치 태그를 새 버전으로 바꾸는 PR | Product Engineer |
| 3 | 관리자 페이지에서 설치 태그를 새 버전으로 바꾸는 PR | Product Engineer |
| 4 | 각 앱의 PR 전 점검 통과, 화면 확인 | Product Engineer |

- 앱은 태그를 명시해 설치하므로 디자인 시스템을 릴리스해도 앱이 자동으로 바뀌지 않음. 앱의 PR이 머지되어야 반영됨
- `v0.1.x`에서 `v0.2.0`으로 올릴 때는 불러오는 경로를 함께 수정. 경로는 design-system 저장소 `README.md` "Usage"
- 두 앱의 스타일 방식이 다름. 웹사이트는 CSS 변수와 토큰 참조 객체, 관리자 페이지는 Tailwind 테마를 사용 2026-11-25 기준 frontend, frontend_admin 모두 `package.json`에 디자인 시스템 의존성 없음(미설치). 최신 태그는 `v0.1.1`
- 앱 점검 항목: `products/website.md`, `products/admin.md`

## 호환되지 않는 변경의 순서

| 순서 | 작업 |
|---|---|
| 1 | 디자인 시스템에 새 이름·새 경로를 추가하고 옛것을 유지한 버전 릴리스 |
| 2 | 두 앱이 새 이름·새 경로로 전환해 배포 |
| 3 | 디자인 시스템에서 옛것을 삭제한 버전 릴리스 |

- 앱이 태그를 고정해 설치하므로 순서 1을 생략하고 한 번에 바꿔도 앱이 즉시 깨지지는 않음. 다만 두 앱의 전환 시점이 어긋나면 서로 다른 버전을 쓰는 기간이 생기므로 위 순서를 기본으로 함
- 삭제 전 확인: 두 앱에서 옛 이름·옛 경로를 검색해 0건인지 확인
