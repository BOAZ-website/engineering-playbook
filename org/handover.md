# 인수인계

서비스운영팀은 약 6개월마다 기수가 바뀜. 이 문서는 기수 교체 체크리스트

## 결정 사항

| 항목 | 규칙 |
|---|---|
| 인수 확인 조건 | 인수받는 사람이 playbook대로 한 번 해 보고 어긋난 부분을 PR로 고침 |
| 권한 이전 | 신규 보유자 확정 후 퇴임자 권한 회수 |
| 총괄 | PM |

- 근거: 규칙이 사람을 따라 사라지는 문제를 막기 위함
- 근거: 직접 실행해야 문서의 빈 곳이 드러남

## 시점

| 시점 | 작업 |
|---|---|
| 기수 교체 4주 전 | 인수인계 이슈 생성. 항목별 담당과 기한 지정 |
| 기수 교체 2주 전 | 권한 이전, 진행 중 작업 정리 |
| 기수 교체일 | 퇴임자 권한 회수 |
| 기수 교체 2주 후 | 인수 확인(playbook 실행 결과 PR 머지) |

- 시즌 전환 기간과 겹치면 PM이 일정 조정(`process/release.md`)
- 기수 교체일 [확인 필요: 다음 기수 교체일]

## PM 팀 교체

기수마다 PM 팀을 새로 만들어 운영 배포 승인자와 playbook PM 예외를 넘김. 팀 이름 규칙: `process/release.md`의 "PM 팀 이름"

| 순서 | 작업 | 담당 |
|---|---|---|
| 1 | 새 기수 PM 팀(`n`th-PM) 생성, 신임 PM 추가 | GitHub 조직 소유자 |
| 2 | 새 팀에 backend, frontend, frontend_admin, product-infra 읽기 권한 부여 | GitHub 조직 소유자 |
| 3 | 4개 저장소 `production` 환경 승인자에 새 팀 추가, Product 담당 승인자를 새 담당자로 교체 | 저장소 관리자 |
| 4 | engineering-playbook `main` 보호 규칙의 PM 예외 팀을 새 팀으로 교체, 저장소 maintain 권한 부여 | GitHub 조직 소유자 |
| 5 | 다음 운영 배포에서 신임 PM 또는 새 담당자가 승인할 수 있는지 확인 | 신임 PM |
| 6 | 이전 PM 팀을 환경 승인자와 playbook 예외에서 제거 | GitHub 조직 소유자 |

- 새 팀을 먼저 추가하고 확인한 뒤 이전 팀을 제거함. 순서를 바꾸면 승인자가 없는 기간이 생김
- 승인자는 저장소 읽기 권한 이상이 있어야 함

## 시크릿과 키 교체 대상

| 종류 | 교체 조건 |
|---|---|
| 퇴임자가 알고 있던 시크릿 | 교체 |
| 개별 발급한 API 접근 키 | 폐기 후 재발급 |
| 서버 환경 변수의 인증 서명 값 | 교체 시 사용자 재로그인 영향 확인 후 결정 |
| 소셜 로그인 앱 자격 값 | 퇴임자가 소유자면 이전 또는 교체 |
| OpenAPI 스펙 접근 인증 값 | 교체 |

- 값과 보관 위치는 이 문서에 적지 않음. 비공개 운영 문서 참조
- 교체 일정과 영향은 PM이 승인
