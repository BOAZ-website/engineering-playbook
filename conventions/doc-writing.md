# 문서 작성 규칙

product-infra의 문서 작성 규칙과 공개 저장소 보안 규칙을 팀 공통 규칙으로 옮긴 문서. AI 도구에 문서 작성을 맡길 때도 이 문서를 따르게 함

## 작성 규칙

| 항목 | 규칙 |
|---|---|
| 독자 | 작성 당시 맥락(회의, 대화)을 모르는 팀원이 처음 읽어도 뜻이 통해야 함 |
| 비유 | 쓰지 않음. 뜻 그대로의 말로 작성 |
| 팀 내 조어 | 쓰지 않음. 써야 하면 무엇인지 풀어 씀 |
| 표준 기술 용어 | 그대로 사용(API, ERD, 스키마, PR 등). 과하게 풀어 산출물 이름이 사라지지 않게 함 |
| 도메인 용어 | 기수, 트랙, BASE·ADV·스터디, HOST 계정 등은 그대로 사용 |
| 작성자 전용 식별자 | 커밋 해시, 워크플로 실행 번호, 개인 GitHub 계정명 기재 금지 |
| 찾아갈 수 있는 대상 | 저장소·브랜치 이름, 파일 경로, PR·이슈 번호는 기재 가능 |
| 추적 기록 예외 | CI 장애·검증 기록은 커밋 해시와 워크플로 실행 주소 기재 가능 |
| 담당 | 실명 대신 역할명(PM, Product Engineer) |
| 날짜 | `2026-11-24` 형식의 절대 날짜. "다음 주", "금일" 금지 |
| 영어 설정 이름 | 하는 일을 한국어로 풀고 필요하면 괄호에 원래 이름 병기. 예: 관리자에게도 규칙 적용(enforce admins) |
| 종결 | 개조식 명사형(`-함`, `-됨`). 절차 문서만 명령형 |
| 확정 결과 | 완료 항목은 "채택", "확정"으로 기재. 경과·진행형 표현 제외 |
| 추정, 미확인 | 추정은 `(추정)`, 미확인은 `[확인 필요: 항목]` |
| 금지 표기 | 이모지, 생성 도구 표기 |

### 고치지 않는 것

- 회의 발언 기록 원문
- 외부 자료 인용
- 코드 블록
- 다른 문서가 링크하는 파일·폴더 이름

### PR·이슈 본문

- 저장소 템플릿(`.github/PULL_REQUEST_TEMPLATE.md`, `.github/ISSUE_TEMPLATE/`)의 섹션 이름과 순서 유지
- 템플릿에 없는 섹션 추가 금지
- 템플릿에서 내용이 없으면 삭제하라고 안내한 섹션만 삭제
- 문서 작업 중 템플릿 파일 자체는 수정하지 않음
- 연결된 Notion 티켓이 있으면 첫 섹션 안에 티켓 이름 기재(내부 링크 금지 규칙 우선. 이름으로 지칭)

## 공개 저장소에 적지 않는 것

| 분류 | 적지 않는 것 | 대신 쓰는 방법 |
|---|---|---|
| 개인 정보 | 실명, GitHub 계정명, 이메일, 연락처 | 역할명 |
| 내부 링크 | Notion, Google Drive, Figma, AWS 콘솔, Discord | "팀 Notion의 ○○ 페이지" |
| 시크릿 | 비밀번호, 토큰, 키, `.env` 값, 시드 계정 비밀번호 | `.env` 예시는 키 이름만 쓰고 값은 비움 |
| 계정·자원 | 계정 ID, ARN, 자원 ID(VPC, 서브넷, 보안 그룹, 인스턴스, CloudFront 배포, Route53 영역 등) | 역할명. 예: "api CloudFront 배포" |
| 네트워크 | 공인 IP, 허용 IP, 호스트명, EC2 퍼블릭 DNS | 역할명. 예: "운영진 개인 IP" |
| 설정 경로 | SSM 파라미터 경로, 웹훅 주소, 그룹 메일 주소 | 역할명 |
| 개인 데이터 | 개인정보가 담긴 SQL, CSV | 저장소에 올리지 않음 |

- 자원 ID와 계정 ID가 필요한 기록은 비공개 위치에 보관. 위치 이름만 안내
- 위치: 팀 Notion의 비공개 페이지 또는 비공개 저장소. 공개 저장소에서는 위치의 이름만 가리킴

## 원문을 옮길 때

- 원본 Notion 자료와 AWS 조회 결과에는 실명 멘션과 실제 값이 섞여 있을 수 있음
- 문장과 값을 복사하지 않고 규칙만 뽑아 새로 작성
- 시크릿은 조회 자체를 하지 않음(SSM 복호화, RDS 비밀번호 조회 금지)

## 커밋 전 점검

| 점검 | 방법 |
|---|---|
| 민감 값 검사 | 저장소의 검사 스크립트 또는 pre-commit 훅 사용(product-infra는 `scripts/check-sensitive.sh`, `.githooks/pre-commit`) |
| 훅 활성화 | `git config core.hooksPath .githooks` |
| 검사 우회 | `--no-verify` 금지 |
| push protection 차단 | 우회하지 않고 값을 지운 뒤 커밋을 다시 만듦 |
| 비밀 검사 실패(CI) | 같은 방식으로 값 제거 |
| 검사식 변경 | 테스트 사례를 함께 추가 |

- 이 저장소의 검사: GitHub의 secret scanning과 push protection을 켬. 전용 검사 스크립트는 2027-01 season-down 이후 조직 `.github` 재사용 워크플로와 함께 도입
