# 이슈·PR 공통 규칙

이슈와 PR을 만들고, 머지하고, 닫을 때 모든 저장소에 같이 적용하는 규칙. 제목·커밋·브랜치·이슈 연결 키워드는 `conventions/git.md`, 리뷰 승인 조건은 `conventions/code-review.md`

## 이슈

| 항목 | 규칙 |
|---|---|
| 담당자(Assignee) | 반드시 지정. 이슈를 만든 사람을 지정함. 다른 사람이 작업을 맡으면 그 사람을 추가하거나 바꿈 |
| 유형(Type) | 반드시 지정. 조직 이슈 유형 `Feature`(기능 추가), `Bug`(오류 수정), `Task`(문서·설정·운영 작업) 중 하나 |
| 우선순위 | 반드시 지정. 조직 Project "BOAZ-website project"의 Priority 필드에 `긴급`(분홍), `높음`(빨강), `중간`(노랑), `낮음`(파랑) 중 하나. 기준은 `org/pm-guide.md` "4. 티켓 우선순위"(Notion 티켓과 같음) |
| 라벨 | 작업 종류 라벨 1개는 반드시, 영역 라벨은 해당할 때 붙임(아래 "라벨") |
| 본문 | 저장소 이슈 템플릿 사용. 체크리스트(`- [ ]`)로 완료 조건을 적음 |

- 이유: 담당자가 없는 이슈는 아무도 진행하지 않은 채 남고, 유형과 우선순위가 없으면 목록에서 급한 일을 고를 수 없음
- 이슈를 대신 만들어 준 경우(예: 회의 결정을 PM이 이슈로 옮김)에도 만든 사람을 먼저 지정하고, 작업자가 정해지면 작업자를 추가함

## PR

| 항목 | 규칙 |
|---|---|
| 담당자(Assignee) | 반드시 지정. PR 작성자(작업한 사람) |
| 리뷰어(Reviewer) | 반드시 지정. 작성자가 아닌 사람 1명 이상(PM 또는 해당 Product의 다른 팀원). 리뷰어가 없는 PR은 리뷰를 시작하지 않음 |
| 이슈 연결 | `Closes #번호` 또는 `Refs #번호`(`conventions/git.md` "PR 제목") |
| 본문 | 저장소 PR 템플릿 사용 |

## 체크리스트 완료와 머지·종료

| 대상 | 규칙 |
|---|---|
| PR 머지 | PR 본문의 체크리스트가 모두 체크되어 있어야 머지함 |
| 이슈 종료 | 이슈 본문의 체크리스트가 모두 체크되어 있어야 닫음 |
| 체크하지 못한 항목 | 머지·종료 전에 항목마다 사유를 댓글로 남김. 예: "해당 없음: 엔티티 변경 없음", "후속 이슈 #123으로 옮김". 사유 댓글이 있으면 머지·종료할 수 있음 |
| 확인 | PR은 리뷰어가 승인 전에 확인함. 이슈는 닫는 사람이 확인함 |

- 이유: 체크리스트는 완료 조건이므로, 체크하지 않은 채 머지·종료하면 무엇이 빠졌는지 나중에 알 수 없음
- 후속으로 미루는 항목은 후속 이슈 번호를 사유 댓글에 적음
- 머지로 이슈가 자동 종료(`Closes #번호`)되는 경우에도 같음. PR을 머지하기 전에 연결된 이슈의 체크리스트를 갱신하거나 사유 댓글을 남김

## 라벨

backend 저장소 방식을 모든 저장소에 씀. 이슈와 PR 모두 붙임

| 종류 | 규칙 |
|---|---|
| 작업 종류 라벨 | 반드시 1개. 제목의 `[Type]`과 맞춤 |
| 영역 라벨 | 해당하면 붙임. 저장소마다 기능 영역으로 정함(예: backend의 `recruitment`, `auth`, `monitoring`) |

| 작업 종류 라벨 | 제목 | 색 |
|---|---|---|
| `⭐️ FEAT` | `[Feat]` 새로운 기능 | `#A2EEEF` |
| `🐛 FIX` | `[Fix]` 버그 수정 | `#D73A4A` |
| `🚑 HOTFIX` | `[Hotfix]` 운영 긴급 수정 | `#B60205` |
| `✏️ DOCS` | `[Docs]` 문서 | `#0075CA` |
| `🛠️ REFACTOR` | `[Refactor]` 동작 변경 없는 구조 개선 | `#FBCA04` |
| `🧁 STYLE` | `[Style]` 포맷팅 등 동작 변경 없음 | `#F9D0C4` |
| `🔎 TEST` | `[Test]` 테스트 코드 | `#C5DEF5` |
| `🚀 RELEASE` | `[Release]` `dev` → `main` 릴리스 | `#0E8A16` |
| `🧹 CHORE` | `[Chore]` 빌드·설정 등 부수 작업 | `#BFD4F2` |

- 이름·색·설명은 모든 저장소에서 같게 둠. 영역 라벨은 저장소마다 다르게 둠

## 템플릿

이슈 템플릿 1종과 PR 템플릿 1종을 모든 저장소에서 같은 모양으로 씀. 섹션 이름과 순서가 같고, 저장소에만 필요한 확인 항목은 정해진 칸("저장소별 확인")에만 넣음

| 템플릿 | 섹션(순서 고정) |
|---|---|
| 이슈 | 작업 내용(무엇을 왜) / 작업 상세 내용(체크리스트, 완료 조건) / 영향 범위 / 참고 |
| PR | 개요(`Closes #` 이슈 연결 줄) / 주요 변경 사항 / 상세 내용 / 확인(공통 체크리스트) / 저장소별 확인 / 참고 |

- PR 공통 체크리스트: 연결된 이슈의 체크리스트를 갱신했거나 사유를 남겼다, Assignee와 Reviewer를 지정했다, 공개 저장소 규칙(실명·계정 ID·시크릿 없음)을 지켰다
- 저장소별 확인 예: backend 마이그레이션 파일, product-infra Terraform plan과 보호 리소스, playbook 최종 검토일
- 모양은 이 문서가 기준. 저장소 템플릿을 바꿀 때 이 문서를 먼저 고침
